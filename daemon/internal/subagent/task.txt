Hand a self-contained job to a subagent, a separate assistant that works in its own conversation and sends back one final message.

Pick the subagent by name with subagent_type. The types are listed at the end of this description.

Do the job yourself when it is small: reading a known file, looking up one definition, or searching inside a few files is quicker done directly. Also work directly when no listed type suits the job.

How it works:
- The subagent starts with no memory of this conversation. Write the prompt as a full brief: the goal, the relevant paths and facts, what to leave alone, and exactly what its final message must contain.
- Say whether the subagent should change files or only look and report. It cannot tell on its own. If there is a way to check the work, such as a test command, include it.
- Its final message comes back to you as the tool result. The user does not see it, so tell the user what matters.
- The result carries a task_id. Pass that id in a later call to continue the same subagent with everything it already knows; without it, each call starts fresh.
- Several task calls in one message run at the same time. Use that for independent jobs.
- While a subagent works on something, do not do the same work yourself. Take up a different part, or wait.
- Treat its report as reliable unless it contradicts something you have seen.
- If a type's description says to use it proactively, do so without waiting to be asked.
